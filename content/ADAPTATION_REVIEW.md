# Private recovery authoring review

The overlay covers 56 existing episodes and 112 existing choice/numeric canonical
families. New variants remain in those families; they never create another
independent-family credit or alter base gates/objectives. The bank stays server
side. It must not be appended to the baseline learner question bank to evade
adaptation limits or expose unused answer keys.

Every default numeric task has a separately implemented procedural reference in
`verification/adaptation-reference.py`. All 895 combinations in the declared
finite variable domains are checked. Derivatives additionally use finite
differences; memory addressing, cache sizes, loss denominators, event deduplication,
pipeline scheduling, traffic, optimizer state and benchmark statistics use explicit
independent traces/loops. Finite differences are numerical checks, not a formal
proof for arbitrary real inputs. Decimal audit thresholds use explicitly listed
discrete values. Unsupported syntax is rejected without eval.

The authoring CLI validates its combined course through released SDK 0.2.0 and
checks the learner projection for answer/generator leaks. Executable negative
controls try rehashed wrong keys, changed family/objective/source/prompt, invented
authority, wrong choice answers, exhausted ordinals and invalid reference inputs.
The generation and verification CLI is exercised in actual subprocesses.

Choice tasks include authored correct choices, distinct distractors, rationale and
transfer intent. Shape, binding and exact reviewed-bank membership are checked;
these checks do not automatically certify arbitrary natural-language factual
claims. Changes require renewed subject review, source qualification and a new
implementation digest. Rotating option order is not a new variant or new family.

This overlay is not runtime-authorized. The host must install the exact generator/
verifier implementation, approve its registry and assignment costs, authenticate
stored verification receipts, and apply under enrollment/policy/evidence fences.
The CLI explicitly returns `publicationAuthority: not_granted` and
`proofAuthenticity: not_checked`; a digest is not a credential. Private practical
code families are not covered by this overlay and still need their own fresh
generation/qualification path.

The default course remains bounded. Exhaustion must produce an explicit next
action, such as further teaching within remaining allowance or a reviewed new
task/extension; it never clears old evidence, silently increases an allowance or
weakens the pass standard. The core remains course-agnostic; private subject
references and authoring procedures stay in this repository.
